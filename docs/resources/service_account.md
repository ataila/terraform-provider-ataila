# ataila_service_account (Resource)

A service account: a non-human identity for automation, **identity only** — a name, an owner customer and roles. It cannot sign in, and this resource **never issues a token**: a token for it is minted in the portal, or a GitLab pipeline exchanges its ID token for a one-hour one (`ci_jwt`) once an operator has linked the project in the portal; `ci_links` shows those links, read-only.

Needs a token holding `service-accounts-admin-global` and platform release 1.0.397 or later.

**Destroy deactivates** the account (every token of it stops at once) and needs `allow_destroy = true` on the provider **and** a token minted with destroy allowed. A deactivated account keeps its name: creating the same name again is refused; import it (`name:<name>`) and set `is_active = true` instead.

## Example Usage

```terraform
# An automation identity of the customer, allowed to read users and tenancy.
# No token comes from here: mint one in the portal, or link a GitLab project to
# the account there and let the pipeline exchange its ID token (ci_jwt).
resource "ataila_service_account" "ci" {
  name              = "ci-terraform"
  owner_customer_id = ataila_customer.example.id
  roles             = ["users-read-global", "tenancy-read-global"]
}

output "linked_projects" {
  value = [for l in ataila_service_account.ci.ci_links : l.project_path]
}
```

## Schema

### Required

- `name` (String) 3-48 characters: lower-case letters, digits and `-`, starting with a letter, not ending in `-`. Unique among service accounts; it also names the account's synthetic e-mail address. Changing it renames the account.

### Optional

- `is_active` (Boolean) `true` (the default). `false` deactivates the account, exactly like destroying the resource, and needs the same two switches; every token of it stops at once. Setting it back to `true` re-activates it with its tokens, roles and links.
- `owner_customer_id` (String) Id of the customer this automation identity belongs to; omit it (or set null) for the platform operator's own.
- `roles` (Set of String) The permission keys the account holds, the whole set; its tokens carry at most these. Omit it to leave the roles to the portal. Never `admin` or a privileged role. A key newly added must be grantable and carried by the provider's own token (a token never hands out more than it holds), and no token changes its own account's roles.

### Read-Only

- `ci_links` (Attributes List) The GitLab projects whose pipelines may exchange their ID token for a one-hour token of this account (`ci_jwt`), by issuer and path. Read-only: an operator links and unlinks a project in the portal. (see [below for nested schema](#nestedatt--ci_links))
- `created_at` (String) When the account was created: RFC 3339 in UTC, compared as an instant.
- `email` (String) The account's synthetic e-mail address, which receives no mail.
- `id` (String) The account's user id (a UUID), assigned by the platform: `principal.id` in `ataila_whoami` for its tokens.
- `owner_customer_name` (String) The owner customer's short name; null without an owner.
- `updated_at` (String) When it last changed: RFC 3339 in UTC, compared as an instant.
- `warnings` (Attributes List) What did not go as planned in the last create or change made through this resource. Also reported as warnings when it happens. (see [below for nested schema](#nestedatt--warnings))

- `allow_destroy` (Boolean) Exchanged tokens may archive, delete, deactivate and retire.

## Import

The import command is the same in both CLIs:

```shell
# By id, or by name with the name: prefix. OpenTofu:
tofu import ataila_service_account.ci name:ci-terraform

# Terraform:
terraform import ataila_service_account.ci 0b6f9c2e-4a1d-4f7e-9c3b-2d8e1a5f6b70
```
